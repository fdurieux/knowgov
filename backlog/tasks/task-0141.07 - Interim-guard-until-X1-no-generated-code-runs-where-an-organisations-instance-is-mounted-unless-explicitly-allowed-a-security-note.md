## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
S1's session found, and the coordinator confirmed in demo/docker-compose.yml, that the app container receives the model keys (OPENAI_API_KEY, GEMINI_API_KEY, LITELLM_MASTER_KEY) and the Neo4j password, and that arm-generated code (the M4 suite, the agent's run-suite) executes in that container with network; with docker-compose.instance.yml the organisation's private instance is mounted there read-only. A deployment that sets a model key therefore runs model-written code beside those credentials and that data: the plan's priority-override condition. The maintainer chose (2026-11-05) a security note plus a narrow refusal now, as one small PR before H1, keeping the order E0, S1, H1, H2, X1, S2; X1 remains the real containment.
<!-- SECTION:DESCRIPTION:END -->

## Implementation Plan

<!-- SECTION:PLAN:BEGIN -->
1. Call-site audit of every path that executes model output.
2. harness/execution_guard.py: an instance is mounted when KG_SUBJECT, KG_SUBJECTS or KG_REGISTER resolves outside the checkout; refuse unless KG_ALLOW_UNCONTAINED_EXECUTION=1; the refusal names X1 (task-0141.05) and the variable.
3. Guard at the one loader all execution paths share (measures._smoke), at run.py before the store and the first model call (exit 2), and at the page's Runner.start for an arms run.
4. tests/test_execution_guard.py: both cases on every path, the opt-in, run.py's exit, the page.
5. docs/security.md, both compose files, CHANGELOG Unreleased; a stopgap, never presented as containment.
