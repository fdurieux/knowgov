## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
With the page's modules taking the subject as a value, the server can hold one Subject per id. KG_SUBJECTS names a root or list of roots whose subject.toml files are the subjects (default subjects/); /api/subjects lists id, name and title; every route takes ?subject=, default the first or KG_SUBJECT when set; a header drop-down switches; the arms choice is keyed per subject in the browser; the glossary gains the term subject; the instance file mounts /instance/subjects as the only root.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [ ] #1 /api/subjects lists id, name and title of every subject under KG_SUBJECTS; a subject id not listed returns 404 on every route
- [ ] #2 A header drop-down switches the page between subjects without a restart; the arms choice is kept per subject in the browser
- [ ] #3 The stack job asserts both public subjects through one stack; an instance started with the instance file lists its own subjects only
- [ ] #4 The glossary entry subject and the page's new sentences pass the glossary test
