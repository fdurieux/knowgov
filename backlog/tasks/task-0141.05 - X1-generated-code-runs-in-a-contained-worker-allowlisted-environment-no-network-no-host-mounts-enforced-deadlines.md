## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Every path that executes model output (single-reply arms, agent feedback suites, shell launchers, final grading, the J-F oracle through a platform adapter, never by editing vendored kit bytes) goes through one trusted execution service. A secured feedback path with an unsecured grader is incomplete, and an unavailable isolation backend refuses instead of falling back to the host. Until this passes, generated-code execution stays off wherever real credentials or sensitive mounts are present.
<!-- SECTION:DESCRIPTION:END -->

## Implementation Plan

<!-- SECTION:PLAN:BEGIN -->
Decision-0012 option (b), the sibling worker.
1. harness/execution.py the one route: run(kind, payload, files) to the worker through KG_WORKER_JOBS; on the host only under KG_ALLOW_UNCONTAINED_EXECUTION=1; otherwise refused, never a fall back. attested(): a fresh attestation, every check true. submit(): job dir renamed in whole, result read capped (256 KiB), checked against its kind's shape, the dir removed.
2. harness/worker.py: attest at start (loopback only, no secret-shaped variable, read-only root, uid 65534, no engine socket, Landlock write confinement) and refuse to serve (exit 3) on any failure; heartbeat; each job a process group with an allowlisted environment, rlimits (memory, processes, file size, CPU, core), Landlock writes only beneath its own folder, a wall time at which the whole group is killed and reaped (a subreaper catches a process that left the group), output capped at 1 MiB; harness/worker_job.py runs one job (suite, suite_dir, feedback, probe).
3. harness/measures.py run_suite, run_suite_dir and feedback_runner route through execution.run; the agent's final grading and the arms' single-reply grading follow.
4. harness/agent.py: Sandbox.write a dir-fd walk with O_NOFOLLOW at every step (EXEC-04); one monotonic deadline for the run, the model stream read by a bounded reader with an idle limit (EXEC-08).
5. demo/docker-compose.yml: the worker service (same image, network_mode none, read_only, cap_drop ALL, no-new-privileges, user 65534, mem/pids/cpus, tmpfs /work, a tmpfs jobs volume shared with the app).
6. Tests: tests/test_execution.py (EXEC-04, 05, 07, 08, attestation, results, forgery); tools/check_worker.py on the real container in demo.yml's stack job (EXEC-01..03, 05..07, 09) plus two loosened workers refusing.
7. docs/security.md, CHANGELOG contract change. The seccomp profile only if the stack job shows Landlock refused (coordinator's four conditions).

Two failures, both fixed at the root: (1) EXEC-05 counted the counting probe itself (a probe runs as python -c, so its command line held the marker); the probe now assembles the marker at run time and excludes itself, and the worker waits for the killed group to finish exiting before it reaps, so an escapee reparented late is still caught.
