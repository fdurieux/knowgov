## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
views, register_view and server read the subject through module tables filled from the SUBJECT global at import (34 references, doc-0005), so a second subject cannot be served by the same process. This step makes them read a per-subject object built once from Subject and passed as a value, with no visible change: the harness stays untouched, since it runs as a subprocess with its own environment. Runs land under a folder per subject id and the store status names the loaded scenario's subject, so the next step can list and switch.
<!-- SECTION:DESCRIPTION:END -->
