## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
A request whose Host and Origin both name the same foreign authority must not authorise a local operation. Accepted authorities and origins come from trusted configuration derived from the listener, never from the request; forwarded headers count only behind an explicitly trusted proxy; a token and an origin check are independent. The Neo4j Browser guide's cross-origin GET and OPTIONS keep working.
<!-- SECTION:DESCRIPTION:END -->

## Implementation Plan

<!-- SECTION:PLAN:BEGIN -->
1. Confirm the defect on the code before H1 with genuine HTTP requests.
2. harness/http_boundary.py (stdlib): defensive authority and origin parsing; a policy from configuration and the listener (loopback names on the bound and published ports, the bind address when specific, KG_*_AUTHORITIES, KG_*_ORIGINS, extra origins per route family); check: exactly one well-formed Host in the policy (else 400/421), an Origin when sent in the policy (else 403), null refused; forwarded headers never read.
3. Page: Handler._boundary first in do_GET, do_POST, do_OPTIONS; page_policy from KG_PAGE_LISTEN, the bound port, KG_PUBLIC_PORT (compose: KG_PORT_APP), KG_DEMO_HOST, KG_PAGE_AUTHORITIES, KG_PAGE_ORIGINS; the guides admit KG_BROWSER_URL's origin; write_guard keeps the token and wide-bind rules.
4. MCP: http_policy(bind, bound port) with KG_MCP_AUTHORITIES and KG_MCP_ORIGINS, checked in Handler._guard before the token.
5. HTTP-01..08 in tests/test_http_boundary.py on real HTTP to both servers, the operation counted; docs/security.md (wider bind, reverse proxy), compose, CHANGELOG contract change (the Inspector's origin now configured).
