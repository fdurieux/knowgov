## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
The governed arm's read tool answers from the store through the port (assertions by key, their basis, status and verification, the gaps), not from the flat bundle, so every assertion the arm consulted is logged by id; the baseline arm keeps reading documents. The page then shows, beside the gate, which keys below verified the arm read and whether it marked each as an assumption in its code, which is the flagged-assumption measure at the size of a real task.
<!-- SECTION:DESCRIPTION:END -->

Pull-based context, selected by the manifest ([arms.agent] context = push (today's) or pull): the governed arm's first message carries the verdict, the policy, the index of keys (level, flags, assertion ids) and the names of the verbatim documents; a read_knowledge(key) tool returns that key's bundle section from the gate's result, which the port produced, and every read is logged as the consulted set; the baseline arm's first message carries the document index and read_document pulls; the run record and the page say which context a run had. 4. The page: beside the gate, a Consulted section per run: for each key below verified, read, assumed (M7), flagged (M3); one plain-English sentence on what the arm read and marked. 5. One D3 run of both arms in pull mode, figures beside the push run's in the notes.
