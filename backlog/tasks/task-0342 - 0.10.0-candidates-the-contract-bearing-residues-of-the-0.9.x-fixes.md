## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
The 0.9.x fix-only sessions (task-0311 to task-0315, task-0323, task-0329) left these items unfixed because each needs a contract change, which decision-0016 reserves for 0.10.0 (0.9.x carries fixes only). The re-check (most capable model, high effort) confirmed each; two first listed here proved fixable without one and were fixed in merge train 2. Each remaining item is a proposal, not a decision: the maintainer decides each by a decision record with the four parts before any build.
- C5-1 (task-0313): a reader of RECONCILE.json with an owner. Proposal: a reconcile reader (CLI and MCP) listing stale nodes with their owners.
- B-X2 and R-T1 (task-0314): register_impact on a start whose kind has no step in the walk (realisers; THREAD from a capability, entity, product or org) answers with no edges and no word. The register-impact schema is closed (additionalProperties false), so a word in the answer is a contract change. Proposal: an optional `note` field naming why. Mitigated in 0.9.x: the tool's `walk` description names the kinds each walk starts from, and the page's panel says when the start's kind has no step.
- B-X8 (task-0314): store_status does not name the stage of what it holds (closed schema). Proposal: an optional `stage` field. Mitigated in 0.9.x: the description points to the gate report's `version`, and code_path's free-text reason names the held version.
- B-N9 (task-0329): register_impact with children repeats an edge once per descendant. Deduplicating breaks the equality the MCP tool, the page and the Browser Cypher hold with the vendored register walk (impact.walk_children), which repeats by design; the fix belongs in ieam-register plus a re-vendor, and it changes MCP output.
- B-N2 (task-0329, part): the CI template passes no previous register. KG_REGISTER_PREVIOUS is already a contract setting the page reads (instance/README); having knowgov-gate.sh read it too gives it a new effect, so an instance that sets it for the page would re-stale keys on every CI run (B-N2's own hazard). Proposal: a separate, gate-only setting, or a documented opt-in.
- C2-7 (task-0315, part): a stale digest names no file it came from. Proposal: the error carries the file a stale digest was last recorded for, which needs the digest's provenance stored.
Fixed in 0.9.x after all (no contract change): R3 (task-0329, a reused node's change named in D1's free-text `reason`, #524) and R-T3 (task-0314, `live:false` on an approved link documented as a deprecated or retired far node, #525).
Known-limits candidate, the maintainer's word: N-3 (task-0329), plant-derived digests listed in a manifest trigger check_subject's unchanged-code note after an honest relist; documented only, and check_subject now names each plant Version to list (task-0312 F2).
