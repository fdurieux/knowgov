## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Body size, body-read duration, admitted connections, run count and result size need finite, configurable, documented limits, with framing validated before a body is read and an absolute read deadline as well as any idle timeout. Shares H1's transport-validation helpers; HTTP concerns stay out of the store adapters.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [ ] #1 LIMIT-01..LIMIT-07 of the plan pass against a disposable loopback server with small injected limits
- [ ] #2 n is an integer in 1..maximum on both the page and the MCP envelope; any prior coercion that is refused is recorded as a compatibility change
- [ ] #3 Rejections use documented status codes without traces or secrets, and slots, sockets and subprocesses are released on every refusal, timeout and disconnect
<!-- AC:END -->

## Implementation Plan

<!-- SECTION:PLAN:BEGIN -->
1. Confirm the defects on H1's head with raw sockets.
2. harness/http_boundary.py: Limits from env (max body, absolute read deadline, idle timeout, max connections), read_body (framing before any read: one digit Content-Length 400/411/413, no Transfer-Encoding 411, no Content-Encoding and a JSON type 415), read_json_body (UTF-8 JSON object, 400), BoundedMixin (idle timeout; a per-request deadline that shuts the socket; a request cut by it never dispatched, 408 after a body), BoundedServer (connection cap, 503 with Retry-After on the accept thread, slot released in finally).
3. Page: page_limits (64 KiB), POST requires a Content-Length, run_request types every field and n in 1..KG_PAGE_MAX_RUNS (5), subject typed before subject selection; BoundedServer in main.
4. MCP: mcp_limits (4 MiB for subject_check), read_body before handle_http (JSON-RPC parse error kept), BoundedServer in serve_http.
5. LIMIT-01..07 in tests/test_http_limits.py on a disposable loopback server with small injected limits; docs, CHANGELOG contract change.
<!-- SECTION:PLAN:END -->

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
Baseline on H1's head (raw sockets): a negative Content-Length held the worker (no answer after 4 s); a non-numeric one dropped the connection with no response; n true, 2.9, "3", 1000000 each started a run (n coerced to 1, 2, 3, 1000000); a body announced at 100 bytes with 5 sent held the worker (no answer after 12 s).
Found under parallel load while testing: headers cut by the deadline's shutdown parsed as a body-less POST and reached the runner; fixed (parse_request refuses a request the deadline cut; arrived(body=True) 408; a page POST requires a Content-Length; the UI, knowgov-runs and demo.yml all send one), and a deterministic test added.
Local validation: tests/test_http_limits.py 9/9 per run, 9 runs three at a time, 0 failures; suite KG_TEST_REQUIRE=rdflib 536/537, stdlib 522/537 both subjects.
