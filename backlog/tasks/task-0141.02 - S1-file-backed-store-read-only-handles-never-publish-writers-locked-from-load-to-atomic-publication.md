## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
The rdflib adapter serialises its snapshot on close, so a reader opened before a newer write restores the old graph over it, and a direct serialisation can leave a partial file. Atomic replacement alone does not prevent a stale writer's lost update; the lock is held from before the writer loads its starting snapshot. S2 reuses this contract.
<!-- SECTION:DESCRIPTION:END -->

## Final Summary

<!-- SECTION:FINAL_SUMMARY:BEGIN -->
The store port names its access: open_store(access="read"|"write"). A read handle passes store.READS only, refuses anything else with StoreReadOnly and never publishes; on Neo4j its session runs in read access mode. A writer publishes on commit() (the context manager's clean exit), never on close(); on KG_RDFLIB_FILE it takes an flock on <file>.lock before loading, waits at most KG_RDFLIB_LOCK_TIMEOUT, then StoreBusy, and publishes atomically through a synced temporary file, os.replace and a directory fsync; any failure keeps the previous file and releases the lock; a file that does not parse raises StoreCorrupt and is left as it is. Every caller migrated, the MCP path-clearing workaround removed, a test holds every open_store call (workflows included) to an access. Evidence: ST-01..ST-09 (tests/test_store_persistence.py), baseline failures reproduced on main's adapter, rdflib and Neo4j integration as in the notes; PR #243 (af6f0eb). Compatibility: a recorded contract change (CHANGELOG Unreleased). Remaining: Neo4j loads are not atomic (S2, task-0141.06); POSIX only for a file-backed writer.
<!-- SECTION:FINAL_SUMMARY:END -->
